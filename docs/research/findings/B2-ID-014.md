# B2-ID-014: `exports.X = function(){...}` property-assignment exports are never extracted as candidates

**Severity:** Moderate (coverage gap, not correctness). Confirmed
honest silent drop — zero false edges — not a wrong-answer defect.
**Status:** FIXED (CommonJS Extraction Checkpoint).
`extract/javascript.rs` gained `commonjs_property_function_assignment`,
recognizing `exports.X = function(){...}` and `module.exports.X =
function(){...}` (both map to the new synthetic `kind_hint`
`js_exports_property_function` → `SymbolKind::Function`). Real-corpus
remeasurement on `request/request`: the `hawk.header(...)` call site
(`request.js:1422`) now resolves end-to-end (`resolved_edges=1`),
confirming the fix works fully for a call site entirely inside this
finding's own scope. The `jar`/`parse` call sites surfaced TWO further
real findings during remeasurement, not defects in this fix: (1) a
genuine name collision — `jar` now has 2 real declarations
(`lib/cookies.js`'s `exports.jar` AND `request.js`'s own
`Request.prototype.jar`, itself only now visible per B2-ID-015) made
some call sites to `jar`/`cookie` genuinely, honestly ambiguous or
differently-scoped; (2) `index.js`'s own `request.jar =
function(){...}`/`request.cookie = ...` shape is a DIFFERENT, real
CommonJS idiom (property assignment onto a plain local identifier,
not `exports`/`module.exports`/`.prototype`) — out of this
checkpoint's authorized scope, newly documented as **B2-ID-016**.
Mutation testing: 0 genuine missed. End-to-end golden corpus test
added
(`b2_id_014_exports_and_module_exports_property_functions_are_extracted_and_cross_file_calls_resolve`).

**Discovered by:** B2-EVAL-010 (JavaScript/CommonJS domain standalone
evaluation, `request/request`@`3c0cddc7c8eb60b470e9519da85896ed7ee0081e`).

## The gap

The existing JavaScript/TypeScript extractor recognizes
`function_declaration`, named/unnamed arrow-function assignment, and
class/method shapes, but has no extraction rule for the CommonJS
property-assignment export idiom: `exports.name = function(...)
{...}`. Confirmed on the real `request` corpus: 4 real sites of this
shape exist (`lib/cookies.js:36` `exports.jar`, `lib/cookies.js:8`
`exports.parse`, `lib/hawk.js:46` `exports.header`,
`lib/hawk.js:21` `exports.calculateMac`) — all 4 produce **zero
extracted snapshots**.

## Effect measured (real cross-file call sites, concrete)

Three real, repeatedly-exercised cross-file call sites in this corpus
target these invisible functions, each confirmed via direct source
read and cross-checked against the tool's real output:

- `cookies.jar()` — `request.js:39`, `index.js:76` — target is
  `lib/cookies.js:36`'s `exports.jar`. `real_decl_count_for_"jar" = 0,
  resolved_edges = 0, call_attempts = 0`.
- `cookies.parse(str)` — `index.js:80` — target is
  `lib/cookies.js:8`'s `exports.parse`.
  `real_decl_count_for_"parse" = 0, resolved_edges = 0, call_attempts
  = 0`.
- `hawk.header(self.uri, self.method, opts)` — `request.js:1422` —
  target is `lib/hawk.js:46`'s `exports.header`.
  `real_decl_count_for_"header" = 0, resolved_edges = 0, call_attempts
  = 0`.

All three are total silence: the callee never reaches candidate
status, so no edge, no Ambiguous CallAttempt, and no Unresolved
CallAttempt is ever produced — strictly less informative to a
consuming agent than even an honest Unresolved classification would
be. Zero false edges confirmed in every case checked.

## Fix (CommonJS Extraction Checkpoint)

`commonjs_property_function_assignment` added to
`extract/javascript.rs`, recognizing an `assignment_expression` whose
LHS is a `member_expression` ending in a `property_identifier` (the
export name) and whose RHS is a `function_expression`/`arrow_function`.
The receiver is checked to be literally `exports` or `module.exports`
(`is_exports_receiver`) — a non-function RHS (e.g. `exports.VERSION =
"1.0.0"`) is correctly never a candidate, out of this checkpoint's own
scope (callable candidates only).
