M6.7 adversarial audit of M6.6's windows_job.rs underway. Findings fixed so far, each with a failing-before/passing-after test: (1) Critical use-after-free - UpdateProcThreadAttribute's PROC_THREAD_ATTRIBUTE_JOB_LIST lpValue pointed at a temporary HANDLE (&job.raw()) gone before CreateProcessW read it; Microsoft docs confirm lpValue must stay valid through DeleteProcThreadAttributeList, not just through UpdateProcThreadAttribute - fixed via a named local. (2) Medium stderr bug - stderr was routed through a throwaway pipe with the read end closed immediately, not real Stdio::inherit() semantics; child crashed once its stderr buffer filled (empirically reproduced, wrong exit code). Fixed with an inheritable duplicate of GetStdHandle(STD_ERROR_HANDLE). (3) Double-close in ContainedChild::start_kill - `self.job = replacement` dropped the already-manually-closed old job handle a second time; narrow wrong-object-closed risk under handle-value reuse. Fixed via mem::replace + mem::forget. Bonus: two M6.6 "grandchild containment" tests were passing vacuously since M6.6 because a cmd.exe parenthesized-grouping-with-quotes script never actually launched the grandchild - only became visible once the stderr fix stopped swallowing the resulting cmd.exe error. Replaced with a working Python-based grandchild script; both tests now genuinely exercise tree-wide kill. All 20 windows_job tests pass. Still auditing: handle inheritance proof, env isolation adversarial, quoting round-trip, MCP protocol ordering regressions, audit integrity, authorization bypass attempts. Not yet committed.
