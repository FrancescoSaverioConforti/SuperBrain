Reproduced empirically on Windows by 4th whole-branch review: a hard link at root/note-a.record to a file outside the vault causes read_note and propose_and_commit's version check to both silently operate on the outside file's content/version, identical effect to pre-fix I-C. A2's design for closing SEC-001/SEC-002 must use one mechanism covering all three: open the handle without following links (O_NOFOLLOW/openat, FILE_FLAG_OPEN_REPARSE_POINT on Windows), then verify the OPENED HANDLE itself (regular file, link count == 1, final path inside root) -- not more path-level checks before the I/O, which is the pattern that already failed 3 times in a row (I-C, then SEC-002, now this).
