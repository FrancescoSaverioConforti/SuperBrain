Reproduced empirically (2026-10-27): root/note-a.record symlinked to root/note-b.record causes read_note(note-a) to return note-b's content+version, and propose_and_commit(note-a, expected=note-b's version) to succeed, replacing the symlink with a real file (note-b itself untouched). No escape, no write-through corruption, but real integrity issue (wrong content/version attributed to the wrong note id). Judged acceptable scope boundary for I-C specifically (which is about escaping the root) by 3rd-wave scoped re-review, not a merge blocker under A1's non-adversarial threat model. Natural fix: reject ANY symlink at a record path (vault never creates one itself) -- same mechanism needed for SEC-001's handle-based I/O work, so closing both together in A2 costs nothing extra. Currently only in evidence.md and the fix-wave report; this is its first stable tracked reference.
