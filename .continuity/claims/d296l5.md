Read-only M6 (External MCP Execution Governance) architecture/roadmap presented for user review, nothing implemented yet. Key findings, independently verified:

- mcp-client has zero path dependencies (rmcp/tokio/serde_json only) and nothing in the workspace depends on it either -- it's a completely unwired leaf crate. Confirmed via direct Cargo.toml grep.
- ExternalToolMetadata/ApprovalPolicy permission model (authorize(), deny-by-default, exhaustive match) is real and sound, but has NO production caller anywhere -- the only construction site is a #[cfg(test)] fixture in invoke.rs. The gate works; nothing calls it for real yet.
- Three previously-tracked B5-era risks are now CONFIRMED RESOLVED in current source, not open: R1 (MCP_MAX_PAYLOAD_BYTES inert without a launcher -- now wired into serve_stdio.rs), R2 (no client-side line-length cap -- now MCP_MAX_RESPONSE_LINE_BYTES), R3 (unsanitized child env -- now isolate_child_environment's 5-var allowlist). These should close, not reopen, in any future risk register.
- ScopeLimits (filesystem/network) are purely advisory -- a string field compared in authorize(), never OS-enforced. This is the primary open gap for unsupervised autonomy.
- Recommendation given (not yet decided by user): Windows Job Objects + resource limits first (reuses already-vetted `windows` crate, closes subprocess-tree-escape concretely), low-privilege user account next, AppContainer/container/WSL2 deferred as future-autonomy-tier.
- M5's 4 inherited residual risks (Unix validation d291h4, fault-injection seam, SQLite busy_timeout, reconciliation tooling -- all under d294jw) are explicitly unchanged/separate from M6's own scope.

Two explicit STOP decisions still pending user input before any M6 implementation: (1) does the new mcp-client audit event schema live inside mcp-client itself or a new sibling crate; (2) adding a correlation_id field to InvocationLogEntry (currently has none). The Job-Objects-first process-isolation choice is also not yet confirmed by the user -- this was a recommendation, not a decision.
