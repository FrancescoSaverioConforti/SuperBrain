Corrected during M5 design review: an attacker who saves a genuinely-valid (audit.log, head.ref) pair and restores both together later produces a pair that passes every check a hash chain + DPAPI envelope can perform (the envelope is real, not forged). This is the identical structural gap the prior security audit already found and accepted for vault-security::deletion_log (DL-04, "Partially Mitigated... autenticità non è freschezza") — no primitive in this codebase, on either platform, closes it. Closing it would need a genuinely monotonic anchor (TPM, external service) — new infrastructure, not proposed. How to apply: never claim rollback/replay detection for any local hash-chain+DPAPI design in this project without an independent monotonic anchor; state corruption/forgery detection only.
