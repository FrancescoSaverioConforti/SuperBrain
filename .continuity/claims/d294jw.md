Four lower-severity items confirmed present at M5 closure, classified ACCEPTED MVP LIMITATION (not blockers, not unowned future-autonomy items):

1. MCP best-effort event loss: AuditSink::record returns (), try_send silently discards QueueFull/WorkerGone -- no caller-visible loss signal. This is the frozen B5.12 AuditSink contract itself, not fixable without changing that trait.
2. No deterministic fault-injection seam in storage::audit_writer (storage::fault::FaultInjector exists for the A2 journal but was never extended to the audit writer) -- leaves one crash window (status-persisted/outcome-fsync-pending) only reachable by chance via uncontrolled-timing kill tests, not on-demand.
3. SQLite cross-process contention: no busy_timeout in storage/src/journal.rs -- pre-existing storage::Vault property, not audit-specific, discovered during M5 Task 7's own acceptance testing.
4. No reconciliation tool for incomplete attempts: an unresolved ApprovalAttempted/RejectionAttempted with no outcome is honestly represented as unknown (never fabricated), but nothing automatically detects or repairs it.

None of these block M5 closure. See [[d290zo]] and docs/research/M5-DURABLE-AUDIT-CLOSURE.md Sections 6/7/10/11, residual risk register items 2/4/5/7.
