Recording a decision/constraint triggers an automatic git commit of .continuity/claims/*.md (observed: commit 5a60c46 appeared after c1a6fa9 with no action from the session). This caused the M7 closure checkpoint to report "M7 NOT CLOSED" since HEAD != c1a6fa9 as the user expected. Why it matters: any future "verify HEAD is exactly commit X" check will see this same drift whenever a decision was recorded after that commit. How to apply: when checking HEAD against an expected commit, account for possible trailing continuity-only commits (metadata-only, touching only .continuity/) before concluding a milestone isn't closed -- but still surface the drift explicitly rather than silently ignoring it, since the user may want these squashed/excluded before tagging.
