During M6.8 final verification, found cargo test -p mcp-client --lib windows_job:: fails intermittently under default parallel test execution (2 of 14 runs failed, many unrelated tests failing simultaneously with ERROR_INVALID_HANDLE / 0x80070006) but passes 100% reliably (16/16) with --test-threads=1. Root cause under investigation (likely CreateProcessW's bInheritHandles=true handle-table snapshot racing against concurrent CloseHandle calls from other test threads in the same process). This is a test-infrastructure/concurrency issue specific to running many spawn_contained calls concurrently from one process - the real production mcp-client-cli binary only ever calls connect()/spawn_contained once per process run, never concurrently with itself, so this is not believed to be a production vulnerability, but it must be disclosed honestly in M6.8's closure doc rather than claiming the test suite is unconditionally green. Not yet fixed/mitigated as of this record.
