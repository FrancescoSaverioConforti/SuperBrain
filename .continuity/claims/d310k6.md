Empirical finding: %LOCALAPPDATA%\Temp on this host has a separate principal (CodexSandboxUsers) with Modify rights - disproves "random temp dir name is safe enough." Option A (stage both exe+script) rejected: confirmed python.exe depends on sidecar DLLs (python313.dll, vcruntime140*.dll) and install-relative Lib\ tree - copying it alone would silently resolve different DLLs than the hash-verified original, actively unsafe not just incomplete. Recommended Option B: command verified in-place at an operator-maintained, ACL-checked trusted install directory (new validation logic, reuses DACL-inspection); script staged from already-verified bytes into a freshly created per-run directory via CreateDirectoryW + explicit SECURITY_ATTRIBUTES/SE_DACL_PROTECTED (requires enabling windows crate's Win32_Security feature, not currently enabled anywhere in workspace - new unsafe security-critical code). Option C (fail-closed, no staging at all, both command and script require pre-existing trusted ACL'd locations) offered as a simpler fallback if the DACL-construction work is judged too large right now. Explicitly confirmed: transitive import/dependency content remains completely unverified by design; same-user attacker is entirely out of scope for any ACL-based mechanism. Not yet approved; no files modified.
