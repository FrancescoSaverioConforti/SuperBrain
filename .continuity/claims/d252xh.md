get_rules = internal operating/engineering rules (constraints, conventions, security/testing rules, agent operating rules, workflow policy) — existing B2 policy docs can be classified here but only within their real declared scope (scope=code_graph/research/evaluation/mutation_testing metadata, never generalized). get_regulations = external regulatory/legal constraints (GDPR, NIS2, AI Act, etc.) — corpus may be empty today, empty is valid not an error, never conflated with internal rules. get_canon = explicitly canonized authoritative truths (approved architecture, stable decisions, invariants, system contracts) — canonization is explicit, not automatic (a Decision note is not automatically Canon). Precedence: Canon > Rules > ordinary project knowledge; Regulations are a separate external axis, not a rung on that ladder — a regulation conflicting with Canon/Rules must be surfaced as an explicit conflict, never silently resolved, left to a trusted human/policy layer. No NoteType::Rule/Regulation/Canon variants added yet — B5.0 freezes the logical contract only; storage/schema changes (if needed) are a separate, minimal, later task.
