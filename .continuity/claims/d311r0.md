User chose Option C over B (fail-closed trusted-location, reject staging entirely - avoids new DACL-construction unsafe code, preserves exe/script location semantics). Design: new identity::verify_trusted_location walks resolved target path + full ancestor chain to drive root via GetNamedSecurityInfoW/GetAce (read-only inspection only, not construction - safe failure mode, doesn't trigger the STOP condition Option B hit). Empirically confirmed on dev host: leaf directory's OS-resolved effective DACL already reflects inheritance correctly (AreAccessRulesProtected blocks it partway up at C:\Users\<user>), but ancestor directories' own WRITE_DAC/DELETE-shaped grants must still be checked independently since inheritance-blocking itself is mutable by anyone holding WRITE_DAC on an ancestor. Existing storage::handle_safety already closes symlink/reparse-point/hard-link identity-swap (reused, not duplicated) - this new check adds only the ACL/ancestor-permission layer. TOCTOU framing: this is an access-control elimination claim for principals outside an allowlist (current user + SYSTEM + Administrators), explicitly NOT a race-free claim. No staging of command or script; no new crate dependency (enables windows crate's existing Win32_Security/Win32_Security_Authorization features). Windows-only; no Unix work claimed. Awaiting explicit go-ahead to implement.
