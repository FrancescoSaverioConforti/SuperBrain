Rejected: exporting brain-api::cli's trusted_ctx()/parse_id() as public functions so an async CLI wrapper could reuse them without duplicating logic. This would have let external code obtain a trusted RequestContext without going through run_cli's own dispatch, contradicting tests/layering.rs's frozen invariant that run_cli alone carries approval authority with no caller-forgeable trust parameter.

Resolved instead: added run_cli_durable as a second, deliberate sibling to run_cli, inside brain-api::cli itself (same module, same private trusted_ctx()/parse_id(), never exported). Its DurableApprovalHooks closures see only plain data (Uuid, &str, &Result<CommitResult, BrainApiError>) -- never RequestContext/WritePolicy/TrustedLocalToken -- so hooks cannot construct, inspect, or influence trust. Any future extension of the durable-audit path (approval, rejection, or elsewhere) must follow this same shape: new trusted entry points live inside brain-api::cli, hooks/callbacks stay data-only.

See also [[d285ij]] (audit worker composition-root ownership, same M5 task series).
