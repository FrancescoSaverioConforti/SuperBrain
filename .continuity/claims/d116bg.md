Final whole-branch review of the B2-ID-008 ImplFact fix (plan 2026-11-07-b2-id-008-implfact.md) found a real Critical bug: incremental_reindex resolves impl_facts against final_snapshots (includes lineage-superseded old snapshots kept only so LineageEdge.from has a valid endpoint), not current_snapshots (the pool resolve_all_typed_edges correctly uses). Any ordinary edit to a file defining a trait/type creates an exact-match lineage edge, so old+new snapshots coexist under the same name -> Implements-edge resolution goes Ambiguous -> edges silently vanish on incremental updates even though a full reindex of the same commit still produces them. The 7 Ambiguous self-type-resolution cases already visible in sharkdp/fd's own evidence file ARE this bug, not a benign quirk. Ruling: real and load-bearing, fix before closing -- bundled with 4 Important (I1 path-style trait names mis-extracted as inherent; I2 evidence arithmetic doesn't reconcile; I3 name-only resolution risks a false edge if enum/struct shares a name with an unrelated trait; I4 planned identity function silently dropped) and 3 Minor findings into one fix wave, per the no-second-fix-wave rule.
