Verified fact: api::search/index today only queries vault Markdown notes (NoteMetadata + text_searchable). No tree-sitter indexer is wired to this API; B2 code graph lives in an unmerged worktree and is out of B3 scope per B3.0. Code layer approach: real code from frozen repos (SuperBrain, controllore@ec274f4680c19f5b335a01a7a563c8f64546e7e2) is curated into NoteType::Code vault notes (frontmatter + body with signature/snippet/path), preserving explicit provenance (repository, commit, original path, symbol/section). This is NOT raw-repository indexing: pipeline is real code source -> curated/frozen code notes -> existing B1 retrieval. Vault is empty today, so the note layer is also a curated benchmark corpus derived from real project material (docs, decisions, findings, patterns), not a production vault snapshot. B3 design doc must state explicitly: 'B3 validates the MVP's note-based retrieval; raw-repository retrieval and graph+text retrieval remain separate future capabilities.'
