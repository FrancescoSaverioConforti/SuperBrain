Corrections: (1) destination dedup before re-append must scan the ENTIRE relevant destination audit chain via existing read-only primitives building a set of already-imported SourceRecordIdentity, not just "tail/recent records" — Brain audit can have interleaved later events so the imported record may not be near the tail; a SourceRecordIdentity found more than once in destination is an integrity anomaly, fail closed/report, never silently normalized. (2) checkpoint is bridge-owned only, own file+version schema, atomic write, no storage::Vault change, path not caller-controlled, fail closed on malformed/corrupt checkpoint; checkpoint is an accelerator/recovery aid only — destination audit chain remains the authoritative evidence of import. (3) source relocation must be explicit/trusted, never auto-discovered; after a locator change the bridge verifies the new locator's chain is compatible with last_known_tail — compatible allows rebind, incompatible fails closed; same pathname with an incompatible new chain must NOT reuse the old SourceLogId automatically.
